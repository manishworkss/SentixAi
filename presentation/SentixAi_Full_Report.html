1. Introduction & Problem Statement

In the modern era of digital entertainment, millions of movie reviews are posted daily across platforms like IMDb, Rotten Tomatoes, and Letterboxd. However, manually reading and understanding the overall sentiment behind thousands of reviews for a single film is a time-consuming and impractical task for both audiences and film industry professionals.

SentixAi addresses this problem by building an intelligent, AI-powered movie review platform that automatically:

  • Aggregates real movie reviews from large-scale datasets (IMDB Dataset with 50,000+ reviews)
  • Analyzes the sentiment of each review using Natural Language Processing (NLP) — specifically a DistilBERT transformer model running entirely locally
  • Visualizes audience sentiment through an executive analytics dashboard with real-time metrics
  • Enables social film discovery with a Letterboxd-inspired interface where users can browse, rate, and review movies
Core Innovation: Unlike commercial sentiment analysis APIs (Google NLP, AWS Comprehend) that charge per request, SentixAi runs its AI model entirely on the local machine — achieving zero API cost with complete data privacy.

2. Project Objectives

  1. Build a social movie platform where users can browse popular films, read reviews, and submit their own ratings — inspired by Letterboxd's design philosophy
  2. Implement secure authentication with Firebase Auth (Google & Email/Password) combined with a custom 6-digit OTP email verification system
  3. Ingest real-world movie review data from the IMDB Dataset (50,000 labeled reviews) through an automated CSV ingestion pipeline
  4. Perform automated sentiment analysis on every review using a local DistilBERT NLP model, classifying each as POSITIVE or NEGATIVE with confidence scores
  5. Provide executive analytics via a dashboard showing sentiment distribution, rating trends, aspect-based analysis, and AI-generated insights
  6. Maintain a clean, scalable codebase with TypeScript across both frontend and backend, Prisma ORM for type-safe database operations, and a modular architecture

3. System Architecture & Design

SentixAi follows a modern three-tier architecture consisting of a React-based frontend, a Node.js/Express backend API, and a SQLite database managed through Prisma ORM. The AI layer operates as an embedded service within the backend.

3.2 Data Flow

  1. User opens the app → React frontend loads and fetches movie data from TMDB API (or local fallback)
  2. User clicks a movie → Frontend calls GET /api/movies?title=X to find the internal DB ID, then GET /api/movies/:id/reviews to fetch real reviews
  3. Admin triggers ingestion → Backend reads the IMDB CSV, parses reviews, maps them to movies, and inserts into SQLite via Prisma
  4. Sentiment analysis runs → Background service loads DistilBERT, processes unanalyzed reviews in batches of 50, and stores results in SentimentAnalysis table
  5. Dashboard displays metrics → Frontend queries /api/analytics/overview which aggregates data from Review and SentimentAnalysis tables

6. Frontend — Detailed Explanation

6.1 Application Entry Point (main.tsx)

The entry point renders the root <App /> component inside React's StrictMode for development warnings. The app is mounted on the #root div in index.html.

6.2 Routing & Layout (App.tsx — 828 lines)

This is the largest and most central file in the frontend. It contains:

  • Theme Configuration: A centralized Theme object that controls all colors, fonts, and borders across the entire application. Changing one value here changes the look globally.
  • React Router Setup: Three main routes — / (Home), /movie/:id (MovieDetail), /login (Auth), and /dashboard (Admin)
  • Login/Signup Forms: Full authentication UI with email/password fields, OTP verification step, Google Sign-In button, and animated background with floating glowing cards
  • Dashboard Shell: A sidebar navigation layout with tabs for Dashboard, Ingestion, Movies, Analytics, and Settings
  • Protected Routes: The /dashboard route redirects unauthenticated users to /login. The /login route redirects authenticated users to /.

6.3 Authentication State (AuthContext.tsx)

A React Context that wraps the entire app and provides authentication state to all components:

  • currentUser — The currently logged-in Firebase user (or null)
  • login(email, pass) — Signs in with email and password via Firebase
  • signup(email, pass) — Creates a new account via Firebase
  • loginWithGoogle() — Opens Google OAuth popup
  • logout() — Signs out and clears state

The context uses onAuthStateChanged to listen for auth state changes and re-render the app automatically when a user logs in or out.

6.4 API Client (api.ts)

A centralized API client with a fetchWithAuth() helper that automatically attaches the Firebase ID token to every request. It exports four API modules:

  • MovieAPI — searchMovies(), getMovie(), getMovieReviews()
  • AnalyticsAPI — getOverview(), getSentimentOverTime(), getMovieAnalytics()
  • SentimentAPI — getStats(), getMovieSentiments()
  • IngestionAPI — startImdbIngestion()

6.5 TMDB Integration (tmdb.ts)

This module handles movie data fetching with a two-tier approach:

  1. Primary: If a TMDB API key is configured (VITE_TMDB_API_KEY), it fetches live data from the TMDB API
  2. Fallback: If no API key is available, it returns a hardcoded array of 10 popular movies (Inception, The Dark Knight, Interstellar, etc.) with verified TMDB poster/backdrop URLs

7. Backend — Detailed Explanation

7.1 Express Application (app.ts)

The Express app is configured with the following middleware stack:

  1. Helmet — Sets security HTTP headers (X-Content-Type-Options, X-Frame-Options, etc.)
  2. CORS — Enables Cross-Origin Resource Sharing for frontend-backend communication
  3. express.json() — Parses incoming JSON request bodies
  4. Pino HTTP — Structured request logging with timestamps and response times
  5. Route Mounting — All API routes are mounted under /api/ prefix
  6. 404 Handler — Returns structured JSON for unknown routes
  7. Global Error Handler — Catches unhandled errors and returns clean error responses

7.2 Sentiment Service (SentimentService.ts)

The core AI component that orchestrates sentiment analysis:

  • processPendingReviews(limit) — Fetches up to limit reviews that haven't been analyzed yet, runs them through DistilBERT in batch, and bulk-inserts results into SentimentAnalysis table
  • startBackgroundProcessing(batchSize) — Starts an asynchronous loop that continuously processes pending reviews until none remain. Uses setImmediate() to run non-blockingly and setTimeout(100ms) to yield the event loop between batches
  • getStats() — Returns current processing statistics: total reviews, analyzed count, positive/negative distribution, average score, and processing status

7.3 Transformers Provider (TransformersProvider.ts)

A Singleton class that wraps the DistilBERT model:

  • Singleton Pattern — Ensures the large ML model is loaded into memory only once, regardless of how many requests come in
  • Lazy Loading — The model is loaded on the first request, not at server startup, to reduce cold start time
  • Model: Xenova/distilbert-base-uncased-finetuned-sst-2-english — A 67M parameter transformer fine-tuned on the Stanford Sentiment Treebank (SST-2) dataset
  • Output Mapping: Raw model output ({label: "POSITIVE", score: 0.99}) is mapped to our standard format with normalized scores (-1.0 to 1.0)

7.4 Analytics Service (AnalyticsService.ts)

Handles all dashboard aggregation queries using Prisma's aggregate and groupBy functions:

  • Total reviews, movies, and analyzed review counts
  • Positive/negative percentage distribution
  • Average sentiment score and average rating
  • Rating distribution histogram (1-10)
  • Sentiment trends over time (groupable by day/week/month)
  • Per-movie analytics with aspect-based sentiment breakdown

9. Authentication Flow — Firebase + OTP

SentixAi implements a multi-step authentication system that combines Firebase Authentication with a custom OTP (One-Time Password) email verification step.

9.1 Sign Up Flow

  1. User enters their email and password on the Sign Up form
  2. Frontend sends POST /api/send-otp with the email to the backend
  3. Backend generates a random 6-digit OTP, hashes it with bcrypt, and stores it in the OtpVerification table with a 5-minute expiry
  4. Backend sends a beautifully styled HTML email containing the OTP via Gmail SMTP (using Nodemailer)
  5. User enters the received OTP on the frontend
  6. Frontend sends POST /api/verify-otp with the email and OTP
  7. Backend verifies the OTP hash, checks expiry and attempt count
  8. On success, frontend calls createUserWithEmailAndPassword() from Firebase Auth SDK
  9. Firebase creates the account and returns an ID token
  10. User is redirected to the Dashboard

9.2 Sign In Flow

  1. User enters email and password on the Sign In form
  2. Frontend calls signInWithEmailAndPassword() from Firebase Auth SDK
  3. Firebase validates credentials and returns an ID token
  4. ID token is automatically attached to all subsequent API requests via fetchWithAuth()

9.3 Google Sign-In

  1. User clicks "Sign in with Google" button
  2. Frontend calls signInWithPopup(auth, googleProvider)
  3. Google OAuth popup opens, user selects account
  4. Firebase handles the entire OAuth flow and returns the user object

9.4 Protected Routes

The backend uses a requireAuth middleware that:

  1. Extracts the Authorization: Bearer <token> header from the request
  2. Verifies the token using Firebase Admin SDK's verifyIdToken()
  3. Attaches the decoded user info to req.user
  4. Returns 401 Unauthorized if the token is invalid or expired

10. AI/ML Pipeline — Sentiment Analysis

10.1 Model Selection

The project uses DistilBERT (distilbert-base-uncased-finetuned-sst-2-english), a distilled version of BERT that is:

  • 40% smaller than BERT-base (67M vs 110M parameters)
  • 60% faster inference while retaining 97% of BERT's performance
  • Fine-tuned on SST-2 — the Stanford Sentiment Treebank, a benchmark dataset for binary sentiment classification
  • Runs locally via @xenova/transformers — no Python, no external API, no GPU required

10.2 Processing Pipeline

Step 1: Discovery
   └─→ Query: SELECT * FROM Review WHERE id NOT IN 
              (SELECT reviewId FROM SentimentAnalysis WHERE modelProvider = 'local-distilbert')
              LIMIT 50

Step 2: Batch Inference
   └─→ Pass 50 review texts to DistilBERT pipeline
   └─→ Model returns: { label: "POSITIVE"|"NEGATIVE", score: 0.0-1.0 }

Step 3: Score Mapping
   └─→ POSITIVE reviews: score = +confidence (e.g., +0.95)
   └─→ NEGATIVE reviews: score = -confidence (e.g., -0.87)

Step 4: Database Insertion
   └─→ createMany() into SentimentAnalysis table
   └─→ skipDuplicates: true (idempotent)

Step 5: Loop
   └─→ If more pending reviews exist, yield event loop (100ms) and repeat
   └─→ If none remain, stop and release processing lock

11. Data Ingestion Pipeline — IMDB Dataset

11.1 Dataset Description

The project uses the IMDB Dataset — a widely-used benchmark dataset containing 50,000 movie reviews labeled as either positive or negative. The CSV has two columns:

ColumnDescriptionExample
reviewFull text of the movie review (HTML formatted)"One of the other reviewers has mentioned that after watching just 1 Oz episode..."
sentimentBinary label"positive" or "negative"

11.2 Ingestion Process (CsvIngestor.ts)

  1. Movie Creation: Creates or finds 10 movies in the database (Inception, The Dark Knight, Interstellar, Avengers: Endgame, Fight Club, Forrest Gump, The Matrix, Harry Potter, Lord of the Rings, Black Panther)
  2. CSV Parsing: Uses the csv-parser library to stream-read the CSV file
  3. HTML Cleanup: Strips <br /> tags from review text, replacing them with newlines
  4. Movie Assignment: Each review is randomly assigned to one of the 10 movies using Math.random()
  5. Rating Conversion: Converts sentiment labels to numeric ratings:
    • positive → random rating between 7-10
    • negative → random rating between 1-4
  6. Author Generation: Assigns realistic reviewer names from a predefined pool (Cinephile99, MovieBuff, FilmCritic, etc.)
  7. Duplicate Prevention: Uses Prisma's upsert() with the @@unique([source, externalReviewId]) constraint to skip already-ingested reviews
  8. Limit: Processes the first 500 reviews for performance (configurable)

  • Mobile (sm): 2-column movie grid, stacked layout

16. Challenges Faced & Solutions

ChallengeSolution
Movie poster images not loading from Amazon CDN due to hotlinking protectionSwitched to TMDB's official image CDN (image.tmdb.org) and added <meta name="referrer" content="no-referrer"> to index.html
IMDB Dataset CSV lacks movie names — reviews are generic text with only positive/negative labelsBuilt a mapping system that randomly distributes reviews across 10 movies and converts sentiment labels to numeric 1-10 ratings
DistilBERT model is large (~100MB) and slow to load on first requestImplemented Singleton pattern with lazy loading — model loads once on first request and stays in memory for all subsequent requests
Background sentiment processing blocks the Express event loopUsed setImmediate() for the processing loop and setTimeout(100ms) between batches to yield control back to the event loop
Duplicate reviews when re-running the ingestion pipelineUsed Prisma's @@unique([source, externalReviewId]) constraint with upsert() to make ingestion idempotent
Firebase Auth state not persisting across page refreshesUsed onAuthStateChanged() listener in AuthContext that automatically restores the session from Firebase's IndexedDB persistence

18. Conclusion

SentixAi successfully demonstrates the integration of modern web development practices with artificial intelligence to create a meaningful, real-world application. The project showcases:

  • Full-Stack Proficiency: A complete React + Node.js application with TypeScript across both layers, Prisma ORM for type-safe database operations, and a modular service-oriented architecture
  • AI/ML Integration: A fully functional NLP pipeline using DistilBERT that processes reviews in real-time without external API dependencies — proving that sophisticated AI can be embedded directly into web applications
  • Security Best Practices: Multi-factor authentication combining Firebase Auth with custom OTP verification, bcrypt hashing, token-based API protection, and Helmet security headers
  • Data Engineering: A robust CSV ingestion pipeline with duplicate detection, batch processing, and idempotent operations
  • Premium UI/UX: A Letterboxd-inspired design that balances aesthetic beauty with functional usability, featuring responsive layouts, micro-animations, and conditional UI based on authentication state

The platform is designed with extensibility in mind — the modular architecture, clean separation of concerns, and comprehensive API make it straightforward to add new features like recommendation engines, social interactions, or multi-language support in future iterations.
