2. OOAD DESIGN DIAGRAMS

The Object-Oriented Analysis and Design (OOAD) approach is utilized to blueprint the internal architecture of SentixAI.

2.1 Class Diagram

The Class Diagram defines the static structure of SentixAI by illustrating its classes, attributes, methods, and the relationships among objects.

classDiagram class User { +UUID userId +String email +String role +login() +viewDashboard() } class MovieProject { +UUID projectId +String movieTitle +Date createdAt +addReview() +generateReport() } class ReviewDataset { +UUID datasetId +String sourcePlatform +Int totalReviews +cleanData() +removeSpam() } class NLPEngine { +String modelName +String version +extractAspects() +calculateSentimentScore() } class AgentSwarm { +Int activeAgents +String currentTask +routeTask() +synthesizeInsights() } class AnalysisReport { +UUID reportId +JSON aspectScores +String llmSummary +exportPDF() } User "1" -- "*" MovieProject : Manages > MovieProject "1" *-- "1" ReviewDataset : Contains > ReviewDataset "1" ..> "1" NLPEngine : Processed By > NLPEngine "1" --> "1" AgentSwarm : Triggers > AgentSwarm "1" --> "1" AnalysisReport : Generates >

Detailed Documentation:
- User & MovieProject: A one-to-many relationship where a single studio executive can manage multiple movie projects.
- ReviewDataset: Holds raw unstructured data. It depends on the NLPEngine for processing (Processed By).
- NLPEngine & AgentSwarm: The NLP pipeline handles embeddings and deep learning, while delegating complex reasoning to the AgentSwarm.
- AnalysisReport: The final output object encapsulating all the extracted aspects and the final LLM-generated summary.

2.2 Sequence Diagram

The Sequence Diagram details the dynamic interaction between objects over time, mapping the chronological flow of a single review analysis.

sequenceDiagram autonumber actor User as Studio Executive participant UI as Web Dashboard participant API as Backend API participant Spam as Spam Filter (Linear) participant NLP as ABSA Engine (Transformer) participant LLM as Frontier LLM (Gemini) participant DB as Database User->>UI: Uploads "Dune: Part Two" Reviews CSV UI->>API: POST /api/v1/analyze API->>Spam: run_spam_detection(dataset) Spam-->>API: clean_dataset API->>NLP: extract_aspects(clean_dataset) Note over NLP: Parses Cinematography, Acting, etc. NLP-->>API: aspect_scores (JSON) API->>LLM: generate_executive_summary(aspect_scores) LLM-->>API: final_report_text API->>DB: saveResults(report) DB-->>API: success_ack API-->>UI: 200 OK (Report Ready) UI-->>User: Displays Analytics Dashboard

Detailed Documentation:
- Chronology: The sequence clearly demonstrates the multi-tier AI approach.
- Execution Flow: Raw data is immediately sent to a cheap, fast linear model (Spam Filter) before hitting the expensive Transformer models (NLP Engine).
- LLM Handoff: Once aspects are parsed, the structured JSON is passed to the Frontier LLM to write the final summary, preventing token waste on raw, unstructured spam.

2.3 Activity Diagram

The Activity Diagram maps the 7-Stage workflow of the SentixAI pipeline, indicating decision points and parallel processing paths.

stateDiagram-v2 [*] --> IngestData IngestData --> CleanData: Raw Text CleanData --> Vectorization: Cleaned Text Vectorization --> SpamCheck state SpamCheck <<choice>> SpamCheck --> Quarantine: If Spam/Review-Bomb SpamCheck --> AspectExtraction: If Authentic Review Quarantine --> [*]: Log & Discard AspectExtraction --> ScoreCinematography AspectExtraction --> ScoreActing AspectExtraction --> ScoreStory ScoreCinematography --> AgentSynthesis ScoreActing --> AgentSynthesis ScoreStory --> AgentSynthesis AgentSynthesis --> LLMSummary: Structured Insights LLMSummary --> OutputDashboard: Final Report OutputDashboard --> [*]

Detailed Documentation:
- Decision Node (SpamCheck): A critical branch where review-bombs are quarantined, saving compute costs.
- Parallel Processing: Aspect extraction (scoring cinematography, acting, and story) occurs concurrently to reduce latency.
- Convergence: All parallel outputs converge at the AgentSynthesis state before the final LLM report is generated.

2.4 Entity Relationship Diagram (ERD)

The ERD illustrates the underlying database schema and table relationships that support SentixAI.

erDiagram USERS { uuid user_id PK string email string company_name string plan_tier } PROJECTS { uuid project_id PK uuid user_id FK string movie_title date release_date } REVIEWS { uuid review_id PK uuid project_id FK string raw_text boolean is_spam string source_platform } ASPECT_SCORES { uuid score_id PK uuid review_id FK float cinematography_score float acting_score float pacing_score float vfx_score } REPORTS { uuid report_id PK uuid project_id FK text llm_summary timestamp generated_at } USERS ||--o{ PROJECTS : "creates" PROJECTS ||--|{ REVIEWS : "contains" REVIEWS ||--o| ASPECT_SCORES : "analyzed_into" PROJECTS ||--o| REPORTS : "summarized_in"

Detailed Documentation:
- One-to-Many: One USER can have multiple PROJECTS. One PROJECT contains multiple REVIEWS.
- One-to-One (Optional): Each REVIEW has one associated row in ASPECT_SCORES (only if the review wasn't marked as spam).
- Foreign Keys: Data integrity is maintained by linking child tables directly to their parent IDs (e.g., project_id in REVIEWS).
